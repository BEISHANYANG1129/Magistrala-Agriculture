## 启动和使用

先确保本机 Magistrala 服务正在运行。本次没有修改或重启其 Docker 部署。农业前端需要 Atom 8080；不同页面另外使用 Reader 9011、规则 9008、告警 8050、报表 9017、Bootstrap 9010、ui-backend 9097，以及 HTTP 消息网关。

在项目根目录分别打开两个 PowerShell 终端：

```powershell
Set-Location D:\personal\magistrala\main\Magistrala
powershell -ExecutionPolicy Bypass -File .\run-local.ps1 ui
```

```powershell
Set-Location D:\personal\magistrala\main\Magistrala
powershell -ExecutionPolicy Bypass -File .\run-local.ps1 agent-ui
```

已经运行的服务不要重复启动。前端默认 5173；区域服务固定绑定本机 9025。若前端提示另一个端口，先检查是否已有前端运行，不要关闭来源不明的进程。

1. 打开农业平台，用本机 Magistrala 账户登录。
2. 选择工作区，顶部选择中文或 English。
3. 先在设备和通道页检查已有资源。常用按钮用于创建和编辑，“全部操作”展开更多功能。
4. 进入“消息与视图”选择通道查看 Reader 数据。发送消息时选择设备并输入其密钥；密钥仅用于当前页面请求，不存入 localStorage。消息上传与 Reader 入库是不同步骤，仍需要平台的授权和匹配存储 Rule。
5. 进入“农田分区与设备位置”查看/编辑地图。图上的区域用于展示；AI 归属需在“区域与 AI”显式配置，绘制一个多边形不会自动把所有设备划归该区域。
6. 在“区域与 AI”选择或创建区域，绑定本工作区的传感器、通道及执行器，设置阈值和模拟时长，再发起分析。旧样本过期或缺少数据时会停止分析，不会凭空生成灌溉建议。
7. 分析历史在专用目录保留，刷新页面可以继续查看。执行仍是模拟回执，不会实际打开阀门。

区域服务默认 `reader-demo`：读取真实 Reader，使用模拟分析器，不使用 GPU。界面会显示当前模式。需要真实模型时，在启动区域服务的终端设置 `$env:AGRI_UI_MODEL = 'gemma3:12b'`，再启动 `agent-ui`。只停止自己启动的区域服务，不停止共享 Ollama 或其他任务。真实模式每次专家调用前运行显卡检查，忙碌或无法确认空闲时拒绝本次调用，待资源空闲后重试；不是后台自动排队。

如果更改区域服务地址，需要在启动 Vite 前设置 `AGRI_AGENT_URL`。前端代理保留 Host/Origin 校验所需信息。当前代理配置用于本机开发；生产部署仍需单独配置反向代理和 HTTPS。

## 区域权限和数据存放

集成服务使用当前登录用户的 Bearer 令牌和 `X-Workspace-ID`，通过 Atom 核验工作区访问。修改区域还校验工作区管理权限，并检查设备、通道属于当前工作区。Reader 请求使用调用者令牌，不使用一个所有人共用的管理员令牌。

区域配置只返回当前工作区部分。保存当前工作区时保留其他工作区配置，使用 revision 检测冲突。分析、历史和模拟回执也检查工作区归属。状态目录只允许一个服务实例使用；这不是跨多实例的数据库存储方案。

集成实例的文件位于 `llm/agentv2/runtime/agri-ui/`：

- `registry.json`：区域和绑定配置；首次启动从已有专用示例复制，若没有示例则创建空配置。
- `history/`：该集成实例的分析历史和模拟状态。

旧独立工作台的配置与历史不被替换。`runtime/` 不应提交或分享，其中其他历史测试文件可能含设备凭据。
