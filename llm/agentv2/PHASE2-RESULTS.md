## 控制模块兼容性

新增 ControlPlan/ControlTask：外层保存 workspace/region/mapping_version，内层遵循旧 /control/task JSON。区域必须转换为绑定执行器；灌溉时长来自区域显式配置，模型的 params 不具有覆盖权限。每个设备任务 ID 根据分析建议和设备生成，同一请求稳定不变。

scripts/verify_legacy_contract.py 将原 agriControlService 的 Go 源码、go.mod/go.sum 复制到本目录 runtime 下的独立目录，在该副本中生成测试。使用真实新适配器输出，通过原 HTTP handler 入队，由原 planner/executor 执行日志流程，观察 open_valve 和 close_valve 都指向 valve-north。测试采用明确的合成配置 0.001 分钟，避免长时间等待，不连接任何物理设备或运行中的控制服务。复制前后原文件 SHA-256 一致。

测试确认旧接口两个限制：HTTP 200 的 task executed 仅表示任务入队；相同 task_id 第二次提交会产生第二组开关日志。因此当前独立工作台的幂等保护和“入队不等于完成”区分必须保留。此测试不是对共享控制服务的在线调用，也不是物理执行测试。

第一次隔离测试因旧日志文件句柄没有 Close 方法，导致 Windows 无法清理 Go 的 TempDir；测试随后改为在独立副本内保留日志，子进程结束时关闭句柄。最终测试通过，原模块没有为此被修改。

## 配置与恢复

- 区域创建、编辑、设备绑定、阈值及显式时长；没有配置时长则拒绝模拟执行。
- POST /v1/regions 使用 revision 比较，防止覆盖旧页面上的配置；保存时生成新版本并保存上一份配置备份。
- 同一实例内配置保存、分析、模拟互斥；模型推理期间外部配置变更仍通过内容哈希复核拒绝。
- 可选 state-dir 持久保存分析和模拟回执。写入采用临时文件、Sync、Rename；执行前先保存意图，重启遇到未完成状态标记 unknown，不自动重放。
- 模拟失败、超时或错误设备回执不会报告成功；重复同一分析返回原回执。
- 最多 200 条历史，满后拒绝新增；不会自动删除记录。当前仅支持单实例拥有一组文件，多用户权限、共享目录协调和防篡改审计不是本阶段能力。

### 真实发现的问题和修复

1. 首次冷启动约 71.55 秒，随后触发原客户端 90 秒超时。原默认上下文是 32768，输入约 450 token。现在单次请求指定 8192 上下文；后续加载明显更快，但文件缓存也可能影响耗时，不能把变化全归因于上下文。超时依然会失败退出，不自动增加重试或资源占用。
2. 模型最初把南区 35% 错判成低于 20%。原控制策略已阻止任务，但错误结论仍可显示。新增确定性的 threshold_checks 输入及语义校验，拒绝没有低湿度证据的 soil_dry，拒绝与低湿度证据矛盾或无阈值支持的 soil normal。新增四个回归子测试，确保错误结论不能形成成功分析结果。
3. 修正阈值提示后，模型曾将 knowledge_ids 错放到 finding 内部，严格解析正确拒绝了响应。增加 Ollama 服务端 JSON Schema 生成约束及明确字段层级，仍通过 LangChainGo 调用和解析；未升级依赖或修改其缓存源码。schema 不能代替程序对数值和证据的复核。
4. 一次调用完成后，驱动报告的 GPU 占用尚未回落，下一场景被检查器中止。新增最多 20 秒的短暂空闲等待；每次模型调用前重新检查，不卸载其他任务模型或终止任何任务。keep_alive=0 让本任务每次调用后释放所加载模型。
